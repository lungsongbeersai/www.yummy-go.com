# Branch contract visibility and staff access

The navbar displays the authenticated branch's contract for all store classifications and employee roles, including non-PLC branches. Web, Capacitor and Swan headers use the existing shared `BranchContractStatus`. The web badge shows a system-access label, full expiry date and remaining days without opening a menu; phones use a second navigation row to keep this readable. Normal status follows the chosen accent theme, contracts with 30 days or fewer use warning colors, and expired status uses destructive colors. All colors use the existing light/dark theme tokens, including the decorative header. Immersive POS pages hide the global navbar; the table selection screen places its expiry control beside the 3D Simulator launcher in the header toolbar. This single control is compact below the wide desktop breakpoint and opens the full branch date in a popover; wide displays show the date and remaining days directly. Toolbar groups wrap within the header when space is limited, keeping the clock visible and eliminating a separate expiry row. The POS ordering screen (`/posAll/order`) deliberately omits the expiry panel on mobile, native and desktop layouts to leave room for menus and the cart. This display exception does not change staff access checks. Compact native controls on other screens open the full expiry date and remaining days in a popover. A branch without an end date displays “Expiry not set” instead of a fabricated date or day count. Customer package management and contract edits remain restricted to the existing PLC permissions.

The backend derives `contract_days_remaining` from the employee's current database branch using the `Asia/Vientiane` calendar. A contract is valid throughout its end date and expires on the following calendar day. Null contracts remain undated. A different branch selected in a management screen, request body fields or JWT contract claims cannot change the authenticated branch used for this check.

`/login/check_login` checks expiry after validating the password and account/store status, before issuing any JWT or login cookie. Expired accounts receive HTTP 401 with machine code `BRANCH_CONTRACT_EXPIRED` and minimal branch/date metadata. Wrong passwords retain a generic rejection without revealing contract data. Existing staff JWTs are checked through the same live database session lookup on every protected request. `/access-data` reuses this validated metadata for the navbar without an additional branch query.

An expired response clears browser credentials, disconnects the socket and resets user-scoped stores. The frontend redirects to public `/subscription-expired`, which explains how to contact YummyGo for payment and renewal. New logins and session validation share the same expiry handling. Ordinary unauthorized responses and network/server failures remain distinct. Requests from an earlier login cannot sign out a newer session, including when the JWT string is identical. The expiry notice remains in memory and does not become a persisted authentication grant.

Open protected pages already validate sessions every 30 seconds and on focus/visibility changes. The backend denies the first protected request after expiry; the existing periodic/focus checks also sign out an otherwise idle page. No browser clock determines whether staff access is granted.

After payment is confirmed, an authorized PLC manager records the renewed end date in the existing branch contract settings. A fresh sign-in is then permitted. Expiry does not set `login_active` to an inactive value, and clicking the retry button does not extend a contract. There is no subscription checkout API in this repository: the expired page links to the existing YummyGo Facebook/phone contact instead of pretending to process a payment. Public customer QR and Socket.IO subscription access paths remain separate from this staff login/session policy.

No new database migration is required. The backend deployment already runs the existing branch contract migration before restarting the API. Both backend and frontend changes must be deployed for the complete behavior.

## Verification

Use the installed Node 22 runtime. Frontend checks are `npm run typecheck`, `npm run lint`, `npm test` and `npm run build`. Backend tests use the synthetic PostgreSQL settings documented in its README; production configuration must never be imported by browser fixtures.

`npm run test:contract-expiry:e2e` starts a disposable PGlite database, the actual login route loaded with injected test-only signing/password verification, and real `findSession`/`sessionRejection` reads. It exercises a non-PLC staff login, two branch dates, an undated contract, automatic expiry sign-out, revocation of a previously issued token, wrong-password privacy, fresh expired-login rejection and successful login after authorized renewal. Runtime database calls are asserted to be reads. The fixture never contacts production, sends a message or processes a payment.

Browser artifacts are written to workspace `.work/contract-expiry/`. Ports 3110/3111 and artifact location can be changed with `CONTRACT_E2E_API_PORT`, `CONTRACT_E2E_WEB_PORT` and `CONTRACT_E2E_ARTIFACTS`; `SIMULATOR_CHROME_PATH` selects a Chrome executable.

Verified on 2026-10-29: frontend typecheck passed, 2,637 tests passed across 232 files, and lint completed with no errors and two existing unused-variable warnings in unrelated files. The updated navbar/POS components and browser fixture also passed focused lint. The production webpack build passed, including `/subscription-expired`; its server/client output and CSS include the final tablet breakpoint. The backend suite passed all 1,567 tests using synthetic PostgreSQL settings. HTTP/Socket.IO fixtures require permission to bind to loopback ports.

The final browser run passed all eight scenarios, including ten navbar previews across 320/390/768/1024/1440px, Lao/English, light/dark, emerald/blue and decorative/plain headers. It verified visible dates and remaining-day text, own-branch isolation, no horizontal overflow or overlapping controls, automatic sign-out, rejection of expired credentials and successful sign-in after renewal. Browser errors and external browser requests were empty. `results.json`, `navbar-previews.json`, screenshots and the browser log contain the verification evidence. These checks used local fixtures; no production deployment or contract update was performed.

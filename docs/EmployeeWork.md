# Employee responsibility window

The **My orders** button beside table search opens a responsive window inside `/posAll/tables`, including the native mobile table screen. The existing `/my_orders` page, its store and `/api/v1/posAll/my_sales` API remain unchanged.

The compact window keeps only employee/date, three summary values and short scope tabs in its main controls. Its header, active tab and total use the application theme; the circular close button uses the shared dialog style with a 48px mobile target. General amount/period explanations are available from the information button; filters expand when requested. Real financial/date warnings remain beside affected data. Tabs support touch swipes on the results panel, tap and Radix keyboard navigation, with a moving indicator and reduced-motion support. Only the active scope is mounted. Directional gestures ignore form controls, pagination and nested horizontal tables, distinguish vertical scrolling, and suppress a dragged accordion header's click; all navigation uses the same scoped store action.

The new window uses only authenticated `GET /api/v1/posAll/my_work` and `GET /api/v1/posAll/my_work/report`. Responsibility belongs only to the employee who added each line (`ownership_mode: item_creator`). A bill may have been opened by someone else; its opener is informational context. Every returned line must name the authenticated employee as creator. Empty bill groups, foreign or null creators, duplicated item IDs, an unsupported totals basis and incorrectly scoped item dates fail closed, including direct report rendering. Neither requests nor UI controls select another employee or branch. The server verifies the live employee and branch. This is a current owned-item snapshot with shared bill statuses, not a complete audit history or a financial-liability allocation.

**Today**, **earlier unclosed bills** and **unverified item dates** are separate scopes, with separate owned-item counts and totals. The day belongs to each owned line's timestamp, not the bill's opening date. Adding an item today to yesterday's bill puts that item in Today. One bill can appear in Today and Carryover with disjoint owned lines. Carryover and undated show only actionable owned lines on still-open or unknown-state, non-cancelled bills; closing a bill removes its old lines from these scopes even if it was sold on credit. Today's closed or cancelled own lines remain visible as current-day history. Reliable item-insert audit time is preferred; stored record times and unverifiable split/merge provenance are explained visibly. Kitchen state describes only the returned own lines. Check-bill and settlement remain clearly labeled shared-bill statuses. Historical print acknowledgements are not shown as proof that the current version reached a kitchen printer.

The business day runs from 05:00 Asia/Vientiane to the following 04:59:59.999. This feature has its own pure period helper and does not change the legacy 06:00 report helper. The server response samples the authoritative clock; the client advances that sample with a monotonic clock and schedules the next cutoff. Cutoff clears the old list and pending report, returns to page one and reloads. Focus/visibility refresh also handles a device waking after the boundary. Actor, branch, token, permission context, dialog lease and business-day guards prevent late results from restoring an earlier scope, including changes that return to the original identity.

All displayed amounts come from server-projected owned lines and `own_totals`, using `item_net_before_bill_adjustments`. Totals include the employee's own line prices, toppings, item discounts and LAK rounding. A full SET financial group is projected before owner/day filtering so it is charged once across periods; only owned components are exposed. Mixed-owner SET groups remain unknown with an ownership-review notice. Nullable quantity, price and amount remain unknown, including summaries. Whole-bill received, balance, credit, discount, service and VAT money is absent from this DTO, UI and report; none is allocated to individual employees. Main cards show bills containing my lines, my item count, my item total and unclosed-bill count.

**Print my report** fetches the complete selected scope and filters, pinned to the displayed business day. It never substitutes the current list page. The API returns the complete report or fails above its 1,000-bill/20,000-item limit. The A4 document includes employee, branch, period, filters, owned line details and own totals, with the bill opener and shared statuses labeled separately. Its renderer also rejects ownership/date mismatches before producing HTML and uses the selected application Lao font. Browser printing opens its window within the click gesture, waits for fonts, and rechecks ownership before invoking print. Android uses `AndroidSystemPrint` only when the installed native shell advertises that plugin. Older Play shells use the existing configured report printer through `printer-store`: resolve the device, submit complete owned-item receipt operations with report key `employee_work`, then execute/acknowledge the returned job. This uses the established report-print API and mobile TCP/agent transport without changing their contracts or requiring a new APK. A missing report printer produces a localized setup message. The UI stays busy throughout the operation; an uncertain or partial result is never reported as success, retried automatically, or sent to a second transport. Closing the window, changing filters/sessions, or crossing the business-day boundary invalidates pending preparation. Nothing is stored offline.

The native receipt path also rejects reports exceeding the existing renderer's operation/text limits before creating a job, so its bounded protocol never silently truncates an employee's report.
